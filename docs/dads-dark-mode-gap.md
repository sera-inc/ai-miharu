## 根因

現行 DADS Layer 2 semantic.css に dark surface、chart color、gradient 用の --app-* セマンティックトークンが存在しない。2026-09-27 時点のインベントリは352値（AI仮対応108、保留208、除外36）だった。保留色143値のうち35値に製品拡張トークン候補が付いた一方、108値は継続保留だった。別の使用箇所別評価は138箇所中106候補・32保留。Layer 1 DADS原本は改変不可であり、利用可能なトークンだけを段階適用する。依頼者は本製品パイロットで暗色表示を維持すると決定した。DADS設計書の組織全体U-04は別の判断として未決で、Phase 1/2の移行とアクセシビリティ承認は未完了。

## 推奨案

依頼者の方針に沿い、本製品は『ダークテーマ維持 + Layer 2 拡張案』で進める。Phase 1 対応表の保留208件は未解決のまま正直に記録し、色カテゴリは保留143値のうち35値を製品拡張候補、108値を継続保留とする。Layer 1には触れず、製品内の試験トークンで表示を検証する。DADS上流への正式な追加・配布は今回行わない。CSS一括置換や機能の黙示削除はしない。

## 選択肢

### ダークテーマ維持 + Layer 2 拡張

機能差分: ダークテーマ、暗色グラデーション、ダーク背景でのチャート表示、ブラウザ拡張デモの暗色UIを維持できる。失う機能なし。必要な決定: U-04 でダークモード要、Layer 2 追加トークン承認。コード変更: Layer 2 に新規 --app-* 追加、Layer 3 の参照を --app-* へ段階移行、レガシー値は互換層で隔離。負担: デザインシステム変更レビュー、コントラスト・色覚・視覚回帰テストが増える。

### ダークテーマ廃止 + ライトDADS統一

機能差分: ダークテーマ、暗色グラデーション、ダーク用チャート配色、ブラウザ拡張デモの暗色UI、ユーザーの暗色表示選好が失われる可能性。チャートはライト用トークンが別途必要。必要な決定: U-04 でダークモード不要、削除対象と代替UXの人間承認。コード変更: ダーク関連CSS・トークン参照・テスト・スクリーンショットを削除またはライト値へ置換。負担: 機能削除の厳密テストと移行告知が必要で、黙示削除は不可。

### ハイブリッド隔離: ライトDADS本体 + ダーク・チャート・グラデーションをfeature flagで維持

機能差分: 既定はライトDADS、フラグONで既存ダーク・チャート・グラデーションを維持。完全な機能維持に近いが、二重経路が残る。必要な決定: フラグ運用と終了条件、U-04 判断。コード変更: 既存実装を削除せず互換CSS変数・フラグで包み、新規Layer 3は --app-* のみ参照。負担: Phase 1 未解決0にできない期間が続くため、完了宣言不可。

### 全面刷新でチャート・グラデーションをDADS準拠に再設計

機能差分: 見た目と操作が変わる可能性が高く、既存のチャート種別・グラデーション表現・拡張デモの忠実度が落ちる可能性。必要な決定: 製品UX変更承認、機能等価性の定義、削除許容範囲。コード変更: チャートライブラリ設定とテーマを --app-* ベースへ再実装。負担: 厳密な機能テストとユーザー影響評価が必要。

## デザインシステム側に必要な変更案

- **対象**: Layer 2 semantic.css に dark surface 系 --app-* トークンを新規追加候補として提案。例: --app-surface-dark, --app-surface-dark-elevated, --app-text-on-dark, --app-border-on-dark。現行 semantic.css に存在する既存トークンではなく、追加提案である。 **理由**: 保留色143値のうち35値は拡張候補、108値は未解決が暗色面用途で、現行 semantic.css に dark surface 専用 --app-* が存在しないため。 **検証**: WCAGコントラスト、テーマ切替、視覚回帰、色覚シミュレーション、Layer 1 未改変チェック、Layer 3 が --app-* のみ参照する lint。
- **対象**: Layer 2 に chart color 系 --app-* トークンを新規追加候補として提案。カテゴリ、系列、グリッド、軸、ツールチップ等。現行 semantic.css に存在する既存トークンではなく、追加提案である。 **理由**: チャート用途の保留値に合うセマンティックトークンが現行 semantic.css に存在しないため。 **検証**: チャートスナップショット、凡例整合、色覚多様性、コントラスト、データ系列数の網羅、ライト・ダーク両テーマ。
- **対象**: Layer 2 に gradient 系 --app-* トークンを新規追加候補として提案。暗色グラデーション開始・終了・フォールバック。現行 semantic.css に存在する既存トークンではなく、追加提案である。 **理由**: 暗色グラデーション用途の保留値に合うトークンが現行 semantic.css に存在しないため。 **検証**: 視覚回帰、フォールバック単色、コントラスト、ブラウザ拡張デモ、印刷・高コントラストモード。
- **対象**: Token lint / CI ルール: Layer 3 新規コンポーネントは --app-* のみ参照、raw hex・旧変数・直接値の混入を禁止。 **理由**: DADS 階層制約を守り、一括置換や未承認値を防ぐため。 **検証**: stylelint 等の CI で失敗、例外は人間承認済み allowlist のみ。

## 製品側の移行手順案

1. コード変更: 対応表（現行は [mapping.md](mapping.md) の 143 種。AI 仮対応 31・保留 65・除外 36・未判定 11）の未解決を 0 と偽らない。旧版の色保留 143 値（35 値を拡張候補、108 値を継続保留）は履歴として保つ。
2. コード変更: 既存ダークテーマ、チャート、グラデーション、ブラウザ拡張デモを削除せず、互換CSS変数またはfeature flagで隔離する。新規Layer 3コンポーネントは --app-* のみ参照する。
3. コード変更: 利用可能な --app-* がある箇所だけ、コンポーネント単位・縦スライス単位で置換する。CSS一括置換は禁止。
4. コード変更: ダークテーマ維持の場合、Layer 2 承認後に dark surface・chart・gradient の --app-* を参照するよう、隔離した既存実装を段階移行する。
5. コード変更: ダークテーマ廃止の場合、人間承認済みの削除対象だけを削除し、代替ライト値を適用する。削除機能、失う挙動、テスト変更を明示する。
6. コード変更: 機能等価テストを追加する。対象はテーマ切替、チャート描画、系列色、グラデーション表示、ブラウザ拡張デモ操作、設定保存、アクセシビリティ。
7. コード変更: 視覚回帰テストとスクリーンショットをライト・ダーク両方、または承認された単一テーマで更新する。差分は人間レビュー対象にする。
8. コード変更: レガシー互換層は全テスト通過と人間承認後にのみ削除し、削除 PR で機能削除の有無を明記する。

## 完了と主張できない条件

- U-04 ダークモード要否が人間により決定され、記録されている。
- ダークテーマ維持の場合は Layer 2 の dark surface・chart・gradient 追加 --app-* が承認・実装され、Layer 1 未改変である。
- ダークテーマ廃止の場合は削除対象機能が人間承認され、機能差分と代替が明記されている。
- 現行の実装値 143 種（[mapping.md](mapping.md)）がすべて最終分類され、AI 仮対応は検証済み、保留・未判定は解決済み、除外は証跡付きで確認済みである（2026-09-30 時点は保留 65・未判定 11 が残る）。
- 保留色143値のうち35値の拡張候補と108値の継続保留について、用途別の対応か適切な除外が確定している。
- 移行チェックリストの未解決が0である。
- 人間レビュー承認が実際に記録されている。DeepSeek 仮対応を人間レビュー済みと記載していない。
- ダークテーマ、チャート、グラデーション、ブラウザ拡張デモの機能等価テストが通過している。
- CSS一括置換が行われておらず、Layer 3 新規コンポーネントが --app-* のみ参照している。
